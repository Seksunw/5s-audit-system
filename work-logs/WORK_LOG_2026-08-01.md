## หัวข้อหลัก: Flow การมอบหมายงาน (admin) + การตรวจงานที่ได้รับมอบหมาย (auditor)

## 1. แก้บั๊ก: ปุ่ม "เริ่มตรวจ" ในงานที่มอบหมายใช้ไม่ได้

**อาการ:** auditor กด "เริ่มตรวจ" จากการ์ดงานของฉัน แล้วเด้งกลับหน้าเลือกโรงงาน

**สาเหตุ:** `startAssignedAudit` สั่งไป `audit.html` โดยไม่ส่ง URL params แต่ `initAudit`
อ่านค่าจาก `getParam(...)` เมื่อไม่เจอ plantId/areaId → เด้งกลับ plant.html

**แก้:** ส่ง params ครบ (plantId, plantName, areaId, areaName, areaType, scheduleId)
→ auditor กดแล้วเข้าตรวจพื้นที่ที่มอบหมายทันที ไม่ต้องเลือกพื้นที่เอง

## 2. หลังตรวจงานที่มอบหมายเสร็จ → mark เป็น "เสร็จสิ้น"

- หลัง submit สำเร็จ ถ้ามาจากงานที่มอบหมาย (มี scheduleId) → เรียก `completeSchedule`
  set schedule เป็น `completed` (ไม่ให้ล้มทั้ง flow ถ้าพลาด)
- การ์ดงานยังแสดงอยู่ (ไม่หาย) แต่เปลี่ยนสถานะ:
  - Badge "📅 รอตรวจ" → "✓ เสร็จสิ้น" (สีเขียว)
  - ปุ่ม "เริ่มตรวจ" → ข้อความ "✓ ดำเนินการตรวจเสร็จสิ้นแล้ว" (ไม่มีปุ่ม)
  - การ์ดจางลงเล็กน้อย คงสไตล์ UI เดิม

## 3. คงการเข้าตรวจได้ทั้ง 2 ทาง

- ผ่านงานที่มอบหมาย (ตรงพื้นที่ทันที)
- เลือกพื้นที่เอง (plant → area) แบบเดิม

## เบื้องหลัง

- `getSchedule` คืน `Area_Type` + `Plant_Name` เพิ่ม และรวมงาน `completed` มาแสดงด้วย
  (join `areas(area_name, area_type)` + `plants(plant_name)`, filter status in pending/completed)
- เพิ่ม handler `completeSchedule({ scheduleId })`
- RLS: เพิ่ม policy `schedules_auditor_update` ให้ auditor ที่อยู่ใน `auditor_ids`
  อัปเดตสถานะงานของตัวเองได้ (เดิมมีแค่ staff)

## 5. หน้าตารางตรวจ (Assignment Analytics) — `assign.html`

หน้าใหม่ให้ admin/auditor ดูภาพรวมการมอบหมาย (`2c38605`)

- KPI: มอบทั้งหมด / เสร็จ / ค้าง / เกินกำหนด + แถบความคืบหน้า
- ตารางรายผู้ตรวจ: จำนวนพื้นที่, เสร็จ/ค้าง, **คะแนนเฉลี่ยที่ให้** (ชี้ความเข้มงวด) — แตะชื่อกางดูพื้นที่ทั้งหมด
- ตัวกรอง รอบ + โรงงาน
- RLS จำกัดขอบเขต: admin เห็นทุกคน / auditor เห็นเฉพาะตัวเอง
- ปุ่ม "ตารางตรวจ" ในเมนูด่วน home (ทั้ง admin + auditor)

## 6. ปรับหน้ามอบหมาย (schedule) ให้ใช้ง่ายขึ้น

รื้อ flow เดิมที่ต้องมอบทีละพื้นที่ (`23b660c`, `d6a6d38`, `5243a4d`)

- **เลือกหลายพื้นที่พร้อมกัน (bulk)** — ติ๊กการ์ด → มอบทีเดียว
- **โหมด "ตามพื้นที่" (SET)** — เลือกผู้ตรวจ(หลายคน)+วัน+รอบ ทับให้พื้นที่ที่เลือก
- **โหมด "ตามคน" (ADD)** — เลือกผู้ตรวจหลายคน → ติ๊กพื้นที่ → เพิ่มแบบ union (คนเดิมยังอยู่)
- **แถบวางแผน** ตั้งรอบ+วันครบกำหนดครั้งเดียว ใช้เป็น default
- **ตัวกรอง** ยังไม่มอบ/เกินกำหนด + **ค้นหา** ชื่อพื้นที่
- แก้บั๊ก: nav ทับกล่อง KPI, เช็คบ็อกซ์ทับป้ายสถานะ
- Logic 1 พื้นที่-หลายคน / 1 คน-หลายพื้นที่ คงเดิม (ไม่แตะ DB)

## 7. ระบบ Audit Log (ความปลอดภัยหลังบ้าน)

เก็บกิจกรรมทั้งหมดของแอปลง Supabase (`8fd54b8`)

- **DB trigger `log_activity()`** ติด 5 ตาราง เก็บ INSERT/UPDATE/DELETE พร้อมค่าเดิม→ใหม่ (JSON)
  อัตโนมัติ ไคลเอนต์ bypass ไม่ได้
  - `profiles`, `schedules`, `areas`, `criteria` — ครบ I/U/D
  - `audit_headers` — เฉพาะสร้าง/ลบ (เลี่ยง noise จาก trigger คำนวณคะแนน)
- **Client log** — LOGIN, LOGOUT, SUBMIT_AUDIT (พร้อมพื้นที่+คะแนน)
- **Append-only** — `revoke update, delete` → log แก้/ลบไม่ได้แม้แต่ admin, อ่านเฉพาะ admin (RLS)
- ขยายตาราง `audit_logs`: เพิ่ม entity, entity_id, old_data, new_data
- **หน้าดู log** `logs.html` (admin) — ตัวกรอง + แตะดูค่าเดิม→ใหม่ + ปุ่มเมนูด่วน admin-only

## 8. ปุ่มรีเซ็ตข้อมูล + สคริปต์ล้างข้อมูล (เตรียมไป production)

สำหรับล้างข้อมูลทดสอบก่อนเริ่มใช้จริง (`0dc722f`)

- **ปุ่มในแอป** — หน้าผู้ใช้ (users.html) → "เขตอันตราย" (แสดงเฉพาะ admin)
  - ด่านยืนยัน 3 ชั้น: พิมพ์ `RESET` + ใส่รหัสผ่าน (verify ด้วย Supabase auth) + popup โชว์ขอบเขต
  - RPC `admin_reset_data()` (security definer) — เช็ค admin ที่ DB, client ลบเองไม่ได้
  - **สำรองอัตโนมัติ** ลงตาราง `*_backup` ก่อนลบ, บันทึกการรีเซ็ตลง audit_logs
- **ขอบเขตลบ:** ประวัติ+คะแนน (audit_headers/details), การมอบหมาย (schedules), รูปใน Storage
- **เก็บไว้:** ผู้ใช้, audit log, ข้อมูลตั้งต้น
- ไฟล์ `supabase/reset_test_data.sql` (รันมือ) — ทางเลือกสำรอง มีบล็อกสำรอง/กู้คืน
- ⚠️ สร้างไว้พร้อม แต่ **ยังไม่ได้กดรีเซ็ต** — ข้อมูลทดสอบยังอยู่ครบ
