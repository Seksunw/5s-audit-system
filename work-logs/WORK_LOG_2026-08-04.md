### 3.1 Plant / Area Ranking — ปรับให้อ่านง่ายบนมือถือ

| ก่อน | หลัง |
|---|---|
| เลข % `.78rem` | **`1.05rem` ตัวหนา** + ป้ายระดับใต้เลข (Excellent / Good / Need Improvement) |
| แถบ 5px | 7px · สีตามเกณฑ์ 90/75 · `Math.max(..., 2)` กันแถบหายเมื่อคะแนน 0 |
| เลขอันดับ 3 เป็นสีแดง | เหรียญ ทอง/เงิน/ทองแดง — และ**โชว์เฉพาะเมื่อมีของเทียบกันจริง** (`items.length > 1`) |
| ไม่รู้ว่าคะแนนมาจากกี่ครั้ง | **เพิ่ม "จาก N ครั้ง"** — ranking จาก 1 ครั้ง กับ 10 ครั้ง เชื่อถือได้ไม่เท่ากัน |

เพิ่ม `n` (จำนวนครั้งที่ตรวจ) ใน `avgBy()` ของ `getDashboard()` · CSS ใหม่ `.rk-*` อยู่ใน
`<style>` ของ `dashboard.html` (ไม่แตะ `css/style.css` เพื่อไม่กระทบหน้าอื่น)
CSS เดิม `.ranking-item` / `.rank-*` ยังอยู่ใน `style.css` แต่ไม่มีใครใช้แล้ว

### 3.2 การ์ด "พื้นที่ต้องปรับปรุง" (ใหม่)

เลือก **โรงงาน → พื้นที่ → ครั้งที่ตรวจ** (dropdown โชว์ `วันที่ · %`) แล้วได้:

- แถบสรุป — % + ระดับ + นับข้อที่ตกจากทั้งหมด
- การ์ดเฉพาะข้อคะแนน **0–1** (ตัดข้อ N/A ออก) เรียง 0 ก่อน 1 · ขอบซ้ายแดง/เหลืองตามคะแนน
- หมวด + คำถาม + **หมายเหตุที่ผู้ตรวจเขียน** + รูปประกอบ (กดขยาย)
- ผ่านทุกข้อ → เครื่องหมายถูกเขียว
- **auto-select เมื่อมีตัวเลือกเดียว** ทั้ง 3 ระดับ — ลดคลิกบนมือถือ

## 4. 🔑 กับดักที่เจอ — `getAreas()` ตัด maintenance/cafeteria ออกโดยเจตนา

**อาการ:** เลือกโรงงาน "Maintenance & Utility" แล้ว dropdown พื้นที่ว่างเปล่า

**สาเหตุ** — `js/app.js` ใน `getAreas()`:

```js
} else if (plantId) {
  // โหมดเลือก plant: ตัด cafeteria + maintenance ออก (แยกไปเป็นการ์ดต่างหากที่หน้า plant)
  q = q.not('area_type', 'in', '(cafeteria,maintenance)');
}
```

`plant.html` ออกแบบให้เข้าโรงอาหาร/ช่างผ่าน**การ์ดแยก** (ส่ง `areaType` ไม่ส่ง `plantId`)
ไม่ใช่ผ่านการเลือก plant · และ `initPlant()` ยัง `.filter(p => !['CAF','MTN'].includes(p.Plant_ID))` ด้วย

พอ dashboard เรียก `getAreas({plantId:'MTN'})` → query กลายเป็น
`status='active' AND plant_id='MTN' AND area_type NOT IN (cafeteria,maintenance)`
แต่ `MTN-MU` เป็น `area_type='maintenance'` → **ถูกตัดทิ้ง เหลือ 0 พื้นที่** (`CAF-CF` ก็เหมือนกัน)

> **บทเรียน:** `getAreas()` เป็นฟังก์ชันสำหรับ **"เลือกไปตรวจ"** ไม่ใช่ **"ดูผล"**
> หน้าไหนที่ต้องเห็นทุกพื้นที่ ห้ามเรียกตรง ๆ โดยไม่ส่ง `all: true`

**ทางแก้ที่เลือก (ดีกว่าแค่ปลด filter)**

เปลี่ยนจาก "ลิสต์พื้นที่ทั้งหมดแล้วหวังว่ามีข้อมูล" → **ลิสต์จากผลตรวจจริง**

| ได้อะไรเพิ่ม | |
|---|---|
| **ไม่มีทางตัน** | เลือกอะไรก็มีข้อมูลให้ดูเสมอ ไม่เจอ "ยังไม่มีผลการตรวจ" |
| **เห็นพื้นที่ inactive ที่มีประวัติ** | เช่น `SUP-MU`, `POC-CF` ที่ seed ตั้งเป็น `inactive` — `getAreas()` กรอง `status='active'` ทิ้ง ทำให้ดูผลเก่าไม่ได้ · ตอนนี้ขึ้นพร้อมป้าย "(เลิกใช้แล้ว)" |
| **ทนต่อข้อมูลกำพร้า** | พื้นที่ที่ถูกลบจากตาราง `areas` แต่มี `audit_headers` อยู่ → ยัง fallback ใช้ `plant_id` จาก header ได้ |
| dropdown สั้นลง | เหลือแค่โรงงานที่มีข้อมูล (NIF ที่ยังไม่เคยตรวจไม่โผล่) |
| **เร็วขึ้น** | โหลดครั้งเดียวตอนเปิดหน้า → เลือก plant กรองในเครื่อง ไม่ยิง API ซ้ำ |
| แสดงจำนวนครั้ง | `ช่าง/ยูทิลิตี้ · 3 ครั้ง` |

| ฟังก์ชัน | คืนอะไร |

## 6. 🔒 ช่องโหว่ XSS ที่ปิดไปด้วย

`photo_urls` เป็นคอลัมน์ที่ **auditor เขียนลง DB เองได้** (RLS `details_all` อนุญาตเจ้าของ header)
ถ้าใส่ `javascript:alert(document.cookie)` แล้ว admin กดรูปบน dashboard → XSS
และเพราะ JWT อยู่ใน `localStorage` (ข้อ 1 ของรายงาน security) จะเก็บ token ได้

`escAttr()` กัน quote ได้ **แต่ไม่กัน scheme** → เพิ่ม `safeUrl()`:

```js
function safeUrl(url) {
  const u = String(url || '').trim();
  if (!u) return '';
  if (/^https?:\/\//i.test(u)) return u;                                    // absolute http(s)
  if (/^\/[^/\\]/.test(u) || /^[\w.-]+\.(?:jpe?g|png|webp|gif)(?:\?.*)?$/i.test(u)) return u;
  return '';                                                                // ไม่ผ่าน → ฝั่งเรียก filter ทิ้ง
}
```

ทดสอบ 10 เคสผ่านหมด — บล็อก `javascript:` · `JaVaScRiPt:` (case) · `data:` · `vbscript:` ·
`  javascript:` (นำหน้าด้วยช่องว่าง) · `//evil.com/x.js` (protocol-relative)

> **ควรใช้ `safeUrl()` ทุกที่ที่เอา URL จาก DB ไปใส่ `href`/`src` ในอนาคต**
