## 4. 🔑 กับดักที่เจอ — `getAreas()` ตัด maintenance/cafeteria ออกโดยเจตนา

**อาการ:** เลือกโรงงาน "Maintenance & Utility" แล้ว dropdown พื้นที่ว่างเปล่า

**สาเหตุ** — `js/app.js` ใน `getAreas()`:

```js
} else if (plantId) {
  // โหมดเลือก plant: ตัด cafeteria + maintenance ออก (แยกไปเป็นการ์ดต่างหากที่หน้า plant)
  q = q.not('area_type', 'in', '(cafeteria,maintenance)');
}
```

`plant.html` ออกแบบให้เข้าโรงอาหาร/ช่างผ่าน**การ์ดแยก** (ส่ง `areaType` ไม่ส่ง `plantId`)
ไม่ใช่ผ่านการเลือก plant · และ `initPlant()` ยัง `.filter(p => !['CAF','MTN'].includes(p.Plant_ID))` ด้วย

พอ dashboard เรียก `getAreas({plantId:'MTN'})` → query กลายเป็น
`status='active' AND plant_id='MTN' AND area_type NOT IN (cafeteria,maintenance)`
แต่ `MTN-MU` เป็น `area_type='maintenance'` → **ถูกตัดทิ้ง เหลือ 0 พื้นที่** (`CAF-CF` ก็เหมือนกัน)

> **บทเรียน:** `getAreas()` เป็นฟังก์ชันสำหรับ **"เลือกไปตรวจ"** ไม่ใช่ **"ดูผล"**
> หน้าไหนที่ต้องเห็นทุกพื้นที่ ห้ามเรียกตรง ๆ โดยไม่ส่ง `all: true`

**ทางแก้ที่เลือก (ดีกว่าแค่ปลด filter)**

เปลี่ยนจาก "ลิสต์พื้นที่ทั้งหมดแล้วหวังว่ามีข้อมูล" → **ลิสต์จากผลตรวจจริง**

| ได้อะไรเพิ่ม | |
|---|---|
| **ไม่มีทางตัน** | เลือกอะไรก็มีข้อมูลให้ดูเสมอ ไม่เจอ "ยังไม่มีผลการตรวจ" |
| **เห็นพื้นที่ inactive ที่มีประวัติ** | เช่น `SUP-MU`, `POC-CF` ที่ seed ตั้งเป็น `inactive` — `getAreas()` กรอง `status='active'` ทิ้ง ทำให้ดูผลเก่าไม่ได้ · ตอนนี้ขึ้นพร้อมป้าย "(เลิกใช้แล้ว)" |
| **ทนต่อข้อมูลกำพร้า** | พื้นที่ที่ถูกลบจากตาราง `areas` แต่มี `audit_headers` อยู่ → ยัง fallback ใช้ `plant_id` จาก header ได้ |
| dropdown สั้นลง | เหลือแค่โรงงานที่มีข้อมูล (NIF ที่ยังไม่เคยตรวจไม่โผล่) |
| **เร็วขึ้น** | โหลดครั้งเดียวตอนเปิดหน้า → เลือก plant กรองในเครื่อง ไม่ยิง API ซ้ำ |
| แสดงจำนวนครั้ง | `ช่าง/ยูทิลิตี้ · 3 ครั้ง` |

## 6. 🔒 ช่องโหว่ XSS ที่ปิดไปด้วย

`photo_urls` เป็นคอลัมน์ที่ **auditor เขียนลง DB เองได้** (RLS `details_all` อนุญาตเจ้าของ header)
ถ้าใส่ `javascript:alert(document.cookie)` แล้ว admin กดรูปบน dashboard → XSS
และเพราะ JWT อยู่ใน `localStorage` (ข้อ 1 ของรายงาน security) จะเก็บ token ได้

`escAttr()` กัน quote ได้ **แต่ไม่กัน scheme** → เพิ่ม `safeUrl()`:

```js
function safeUrl(url) {
  const u = String(url || '').trim();
  if (!u) return '';
  if (/^https?:\/\//i.test(u)) return u;                                    // absolute http(s)
  if (/^\/[^/\\]/.test(u) || /^[\w.-]+\.(?:jpe?g|png|webp|gif)(?:\?.*)?$/i.test(u)) return u;
  return '';                                                                // ไม่ผ่าน → ฝั่งเรียก filter ทิ้ง
}
```

ทดสอบ 10 เคสผ่านหมด — บล็อก `javascript:` · `JaVaScRiPt:` (case) · `data:` · `vbscript:` ·
`  javascript:` (นำหน้าด้วยช่องว่าง) · `//evil.com/x.js` (protocol-relative)

> **ควรใช้ `safeUrl()` ทุกที่ที่เอา URL จาก DB ไปใส่ `href`/`src` ในอนาคต**

# ส่วนที่ 2 — 🔒 ปิดช่องโหว่ตาราง `*_backup` (งานค้างจาก 3 ส.ค. — ปิดแล้ว)

## 10. ปัญหา

`admin_reset_data()` (ปุ่ม "รีเซ็ตข้อมูลระบบ") สำรองข้อมูลก่อนลบด้วย:

```sql
create table public.audit_headers_backup as table public.audit_headers;
```

**`create table ... as` มีปัญหา 2 อย่างพร้อมกัน:**

1. **Supabase ตั้ง `ALTER DEFAULT PRIVILEGES`** ให้ตารางใหม่ใน schema `public`
   grant แก่ `anon` / `authenticated` **อัตโนมัติ**
2. **RLS ปิดโดยปริยาย** สำหรับตารางที่สร้างใหม่

→ ทันทีที่กดปุ่มรีเซ็ตครั้งแรก จะเกิด 3 ตารางที่ **ผู้ใช้ที่ล็อกอินคนไหนก็ `SELECT`
ผลตรวจทั้งบริษัทได้** — bypass RLS ทั้งหมดที่ตั้งไว้บน `audit_headers` / `audit_details` / `schedules`

ตอนนั้นยังไม่มีปัญหาเพราะยังไม่เคยรีเซ็ต (ยืนยันจาก query 3 ส.ค. — ไม่พบตาราง `*_backup`)
แต่เป็นระเบิดเวลาที่จะระเบิดตอนกดปุ่มครั้งแรก

## 12. วิธีแก้ — ใส่ทั้ง `revoke` และ `enable RLS`

```sql
revoke all on public.audit_headers_backup from anon, authenticated;
alter table public.audit_headers_backup enable row level security;
```

| ทำไมต้องทั้ง 2 อย่าง | |
|---|---|
| `revoke` | ปิดที่ระดับ **grant** — ถ้าใส่แค่ RLS ตารางจะยังโผล่ใน PostgREST schema |
| `enable RLS` (ไม่มี policy) | **ล็อกตาย** — เข้าถึงผ่าน API ไม่ได้เลย = defense in depth |

**ทำไมไม่สร้าง policy ให้ admin อ่าน:** ตารางสำรองมีไว้กู้คืนผ่าน SQL Editor เท่านั้น
ไม่มีหน้าไหนในแอปอ่าน → ล็อกตายคือ least privilege ที่ถูกต้อง
SQL Editor รันเป็น role `postgres` ซึ่ง bypass RLS จึงกู้คืนได้ปกติ

**ล็อกในทรานแซกชันเดียวกับที่สร้าง** — ไม่มีช่วงเวลาที่ตารางเปิดโล่ง

### เพิ่มส่วน F ใน `patches.sql` — ล็อกตารางที่มีอยู่แล้ว

`DO` block วนหา `*_backup` ทุกตัวแล้วล็อก เผื่อเคยรันเวอร์ชันเก่าหรือ `reset_test_data.sql`

- ใช้ `format('%I')` — ป้องกัน SQL injection ที่ระดับ identifier
- `like '%\_backup'` — escape `_` เพราะเป็น wildcard ใน `LIKE`
  (ทดสอบแล้วไม่จับ `Xbackup` / `my_backup_old`)
- `raise notice` รายงานผล · รันซ้ำได้ 100%

> **หมายเหตุการตั้งชื่อ:** `patches.sql` มีส่วนที่ตั้งชื่อ **"D" ซ้ำ 2 อัน**
> (บรรทัด 147 = RPC รีเซ็ต · บรรทัด 196 = KPI RLS) · ส่วน E ถูกยกเลิกไปแล้ว
> จึงใช้ **F** สำหรับส่วนใหม่

## 13. ⚠️ พลาดตอนรัน — วางไม่ครบ

รอบแรกรันแล้วขึ้น `Success. No rows returned` ดูเหมือนผ่าน
แต่ตรวจด้วย `pg_proc` พบ **`จำนวน_revoke = 0`** → ฟังก์ชันใน DB ยังเป็นเวอร์ชันเก่า

**สาเหตุ:** วางไปแค่ `DO` block (ส่วน F) ไม่ได้วาง `create or replace function` (ส่วน D)
→ ตารางที่มีอยู่ถูกล็อก (ไม่มีอยู่แล้ว = no rows) แต่ฟังก์ชันไม่ได้ถูกเขียนทับ

**บทเรียน:** `Success` ของ SQL Editor **ไม่ได้แปลว่าสิ่งที่ต้องการเกิดขึ้นแล้ว**
ต้องมี query ยืนยันผลเสมอ ไม่เชื่อสถานะ success เพียว ๆ

**query ยืนยันที่ใช้** (เก็บไว้ใช้ซ้ำได้):

```sql
select
  case when prosrc like '%revoke all on public.audit_headers_backup%'
       then '✅ อัปเดตแล้ว' else '❌ ยังเก่า' end                     as สถานะ,
  (length(prosrc) - length(replace(prosrc,'revoke all','')))/10       as จำนวน_revoke,
  prosecdef                                                          as security_definer,
  proconfig                                                          as search_path
from pg_proc
where pronamespace = 'public'::regnamespace and proname = 'admin_reset_data';
```

# ส่วนที่ 4 — 🐛 ตัวเลข "คะแนนที่ให้" ในหน้าตารางตรวจขัดกันเอง

## 23. อาการ (พบตอนทดสอบเป็น admin)

การ์ดผู้ตรวจโชว์ **คุณอ้น 94%** แต่กดเข้าไปดูรายละเอียดมี **พื้นที่เดียวที่ได้ 100%**
เลขไม่ตรงกันและไม่มีอะไรบอกว่า `94%` คืออะไร

## 24. ตัวเลขนั้นคืออะไร

**คะแนนเฉลี่ยที่ผู้ตรวจคนนั้น "ให้" คะแนน** — ไม่ใช่คะแนนของพื้นที่ ไม่ใช่ผลงานของผู้ตรวจ
เจตนาเดิมคือใช้เทียบ **"ความเข้มงวด"** ระหว่างผู้ตรวจ (ใครให้คะแนนสูง/ต่ำกว่าค่ากลางมากอาจต้องสอบเทียบ)

## 25. สาเหตุ — ขอบเขตการกรองไม่ตรงกัน

| ตัวเลขบนการ์ด | กรองด้วย | บรรทัดเดิม |
|---|---|---|
| `N พื้นที่ · เสร็จ x/y` | **รอบ + โรงงาน** | 4098–4099 |
| **`94%` (pill)** | **โรงงานเท่านั้น — ไม่กรองรอบ** | 4113 |
| `เสร็จ · 100%` (badge) | โรงงาน → เอาครั้งล่าสุดของพื้นที่ | 4115 |

อ้นมีพื้นที่เดียวในรอบ 2 ได้ 100% แต่ pill ไปเฉลี่ยรวมกับ audit รอบ 1 (88%) → `(88+100)/2 = 94%`

## 26. ที่แก้ (A + B)

### A) จำกัดขอบเขตให้ตรงกัน

**ข้อจำกัดที่เจอ:** `audit_headers` **ไม่มีคอลัมน์ `audit_round`** → กรองตามรอบตรง ๆ ไม่ได้

วิธีที่ใช้ — จับคู่ผ่าน `(ผู้ตรวจ|พื้นที่)` ที่ปรากฏใน `rows` ที่แสดงอยู่:

```js
const inScope = new Set();
rows.forEach(s => (s.Auditor_IDs || []).forEach(aid => {
  if (aid) inScope.add(aid + '|' + s.Area_ID);
}));

const scoreLU = {};
data.headers.forEach(h => {
  const k = h.Auditor_ID + '|' + h.Area_ID;
  if (!inScope.has(k)) return;          // นอกขอบเขตที่แสดง → ไม่นับ
  if (!scoreLU[k] || (h.Date||'') > (scoreLU[k].date||'')) scoreLU[k] = { pct:h.Percent, date:h.Date };
});

// เฉลี่ยจาก "ค่าที่แสดงจริง" (badge) ไม่ใช่จาก raw headers → pill ตรงกับ badge เสมอ
const scoresByAud = {};
Object.entries(scoreLU).forEach(([k, v]) => {
  const aid = k.slice(0, k.indexOf('|'));   // UUID ไม่มี '|' → indexOf ปลอดภัยกว่า lastIndexOf
  (scoresByAud[aid] = scoresByAud[aid] || []).push(v.pct);
});
```

**จุดสำคัญ:** เฉลี่ยจาก `scoreLU` (ค่าที่แสดง) ไม่ใช่จาก `data.headers` → รับประกันว่า pill สอดคล้องกับ badge

### B) ทำ label ให้ชัด

เพิ่มคำว่า **"คะแนนที่ให้"** ตัวเล็กเหนือ pill (CSS ใหม่ `.asg-give` / `.asg-give-lb` ใน `style.css`)
และเขียนคำอธิบายใต้การ์ดใหม่ให้ระบุขอบเขต:

> **คะแนนที่ให้** = คะแนนเฉลี่ยที่ผู้ตรวจคนนั้นให้กับพื้นที่ <u>ที่แสดงอยู่</u>
> (ไม่ใช่ผลงานของผู้ตรวจ) — ใช้ดู "ความเข้มงวด" ถ้าสูง/ต่ำกว่าค่ากลางมากอาจต้องสอบเทียบมาตรฐานกัน

## 27. ผลก่อน/หลัง (เคสจริงที่พบ)

| ผู้ตรวจ | ก่อน | หลัง |
|---|---|---|
| คุณอ้น | pill **94%** · badge 100% ← ขัดกัน | pill **100%** · badge 100% ✓ |
| คุณมด | pill 88% · badge 88.46% | เหมือนเดิม (ปัดเศษ) ✓ |

ทดสอบเพิ่ม: ถ้าอ้นมี audit ที่โรงงานอื่น (SUP 70%) ก็ไม่ปนเข้ามา ✓ ·
ผู้ตรวจที่ยังไม่มีผลตรวจ → แสดง `—` ไม่ใช่ `NaN` ✓ · UUID parse ถูก ✓

## 28. ⚠️ ข้อจำกัดที่ยังเหลือ (ไม่ได้เกิดจากการแก้นี้)

ถ้าเลือก **"ทุกรอบ"** และพื้นที่เดียวถูกตรวจหลายรอบ →
