## 1.4 งานที่ทำไปแล้วและ "ยกเลิก" (rollback)

สิ่งที่ทำไปแล้วและถูกย้อนกลับ:

## 2.4 แผนแก้ไข 3 ระยะ (ยังไม่เริ่ม)

**ระยะที่ 1 — ความเสี่ยงต่ำ ผลลัพธ์สูง (1–2 วัน)**
ตั้ง password policy · ลด JWT expiry เหลือ 30 นาที · ตั้ง storage limit ·
เพิ่ม `<meta>` CSP · เติม `'` ใน `escHtml()` + ครอบ `escAttr()` 5 จุด ·
ปิด `console.log` ใน production · ลบ email admin จาก SQL · ยืนยัน RLS ใน DB จริง

**ระยะที่ 2 — แก้ทั้ง DB และ client (1 สัปดาห์)**
เลิกเก็บ token เอง ใช้ `getSession()` · บังคับ `auditor_id = auth.uid()` ที่ DB ·
trigger log การแก้ `audit_details` · constraint วันที่/อีเมล ·
จำกัด BOPLA ของ `schedules` เป็น RPC · ย้ายการกรองพื้นที่ไป RLS · `safeError()`

**ระยะที่ 3 — ต้องคุยกับผู้ใช้งานก่อน (2–4 สัปดาห์)**
ล็อกผลตรวจ (`locked_at`) · submit เป็น RPC atomic · fail-closed ·
ปิด public bucket → signed URL · กันตรวจซ้ำ · ย้าย hosting เพื่อได้ HTTP header ครบ ·
ถอด inline `onclick` แล้วถอด `'unsafe-inline'` จาก CSP

## 3.2 🔴 Credential รั่วใน git history — จัดการเสร็จแล้ว

### สาเหตุ (สืบจาก history ได้แน่ชัด)

`.gitignore` **ถูกเขียนทับ** ไม่ใช่เพิ่มบรรทัด — ห่างกัน 1 นาที:

| commit | เวลา | เกิดอะไร |
|---|---|---|
| ก่อนหน้า | — | `.gitignore` มี 15 บรรทัด กัน `URL*.txt`, `Criteria_Master.csv`, `*.docx`, `.obsidian/` ครบ |
| `f944bb9` | 1 ส.ค. 17:39 | เขียน `.gitignore` **ทับใหม่ทั้งไฟล์** เหลือ 3 บรรทัด (`export/`, `*.zip`, `.DS_Store`) → กฎกันไฟล์ส่วนตัว 12 บรรทัดหายหมด → ไฟล์ส่วนตัวถูกดูดขึ้นทั้งชุด (`URL ทั้งหมด.txt` 14 บรรทัด · `Criteria_Master.csv` 133 · `export_to_obsidian.py` 369 · `.obsidian/*` 5 ไฟล์) |
| `38e9afb` | 1 ส.ค. 17:40 | สังเกตได้ใน 1 นาที → `git rm --cached` + เขียน `.gitignore` ให้ครบ |

**จุดที่พลาด:** `git rm --cached` เอาไฟล์ออกจากการ track ต่อจากนี้ แต่ **ไม่ลบจาก history**
commit `f944bb9` ยังอยู่ในสายและยังมีเนื้อไฟล์เต็ม → repo เป็น public + push ไปแล้ว = เปิดเผยจริง

### สิ่งที่ทำ (3 ส.ค.)

**1. ลบไฟล์จาก history ทั้งสาย**

```bash
git filter-branch --force --index-filter \
  'git rm --cached --ignore-unmatch "URL ทั้งหมด.txt"' \
  --prune-empty --tag-name-filter cat -- --all
git for-each-ref --format='%(refname)' refs/original | xargs -n1 git update-ref -d
git reflog expire --expire=now --expire-unreachable=now --all
git gc --prune=now --aggressive
```

| ผล | |
|---|---|
| commit | 84 → 81 (`--prune-empty` ตัด 3 ตัวที่เหลือแต่การแตะไฟล์นี้) |
| ไฟล์แอปทั้ง 33 ไฟล์ | **hash เหมือนเดิม 100%** — ไม่เสียงานเลย (ยืนยันด้วย `git ls-tree -r HEAD` เทียบ backup) |
| รหัสผ่าน Supabase ใน history | ✅ ไม่พบในทุก commit แล้ว |
| HEAD | `41c7c1b` → `c5f1997` → `7fd21c0` (หลัง commit `.gitignore`) |

**2. Force push**

`--force-with-lease` ธรรมดา **ถูกปฏิเสธ (stale info)** เพราะ `filter-branch` ไปเขียน
`refs/remotes/origin/main` ในเครื่องด้วย → git เทียบกับค่าที่ผิด

แก้โดยระบุ SHA จริงของ remote ตรง ๆ (ไม่ต้อง `git fetch` ซึ่งจะดึง object เก่ากลับมา):

```bash
git push --force-with-lease=main:41c7c1b7ddeb5c9ebe12d836a4350a1d0a0d57f9 origin main
# → + 41c7c1b...7fd21c0 main -> main (forced update)
```

**3. ลบไฟล์จากโฟลเดอร์** + ถอดกฎ `URL*.txt` ออกจาก `.gitignore` (ไม่ต้องใช้แล้ว)

### ⚠️ บทเรียนสำคัญที่สุดของวันนี้ — force push ไม่ลบ object บน GitHub

ตรวจหลัง force push พบว่า:

| URL | ผล |
|---|---|
| `raw.githubusercontent.com/.../main/URL ทั้งหมด.txt` | ✅ 404 — หายจาก branch |
| `raw.githubusercontent.com/.../f944bb9.../URL ทั้งหมด.txt` | 🔴 **ยังดึงได้ พร้อมรหัสผ่านเต็ม ๆ** |

force push แค่ย้าย `refs/heads/main` ไปชี้ commit ใหม่ — object เก่ากลายเป็น
**unreachable object** ที่ยังนอนบนเซิร์ฟเวอร์ GitHub และเข้าถึงได้ถ้ารู้ SHA
`git gc` ที่รันมีผลแค่ในเครื่อง · GitHub รัน GC ฝั่งเซิร์ฟเวอร์เมื่อไรไม่มีกำหนด สั่งเองไม่ได้

**สรุป: การลบ history ไม่ยกเลิกการรั่วที่เกิดแล้ว → การเปลี่ยน credential คือทางเดียวที่ได้ผลจริง**

### กฎที่ต้องยึดจากนี้ไป

1. **แก้ `.gitignore` ด้วยการเพิ่มบรรทัดท้ายไฟล์ ห้ามเขียนทับ**
2. **`git status` ก่อน commit ทุกครั้ง** — เห็นไฟล์ที่ไม่คาดคิด = มีอะไรผิด
3. **ห้ามเก็บ credential ในโฟลเดอร์ repo** — `.gitignore` พลาดได้อีก ใช้ password manager
4. `git rm --cached` ≠ ลบจาก history · force push ≠ ลบ object บน GitHub
5. Token เก็บใน macOS Keychain ไม่ฝังใน `.git/config`

## 3.3 แก้ `.gitignore`

เพิ่มกฎกันไฟล์รายงานความปลอดภัยไม่ให้ขึ้น repo:

```
# security — ห้ามขึ้น GitHub เด็ดขาด (repo เป็น public + เสิร์ฟผ่าน GitHub Pages)
# รายงานช่องโหว่ที่ยังไม่ได้แก้ = แผนที่ให้ผู้โจมตี
docs/SECURITY_ASSESSMENT.md
*SECURITY_ASSESSMENT*
*PENTEST*
*.pentest.md
```

ทดสอบแล้ว 4 ชั้น: `git check-ignore` ✓ · `git status` ไม่เห็น ✓ ·
`git add -A` ไม่แตะ ✓ · `git add` ตรง ๆ ถูกปฏิเสธ ✓ · ไม่เคย commit ขึ้นไปเลย ✓
